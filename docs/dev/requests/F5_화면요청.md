## 3. 정해진 표시 방식 (10-29 사용자 결정 — 함수가 이미 반영한 것과 화면에서 할 것)
| 항목 | 결정 | 화면에서 할 것 |
|---|---|---|
| 평소 대비 숫자 | 7일 표시값이 주, 원값은 작게 | `평소대비` 크게, `평소대비_원값` 작게 |
| 점수 구성 | 묶음별 + 사건별 10건 | `load_tension_contrib` 두 표 모두 |
| 상위 % | 첫 365일(2010년) 숨김 | `상위%_표시`가 NaN이면 "—" |
| 주체국 | 못 붙는 5건(보완행)은 "미상" | 그대로 표시 |
| 그림 색 | `config.STAGE_COLORS`·`STAGE_NAMES`에서 읽음(함수가 이미 함) | 색을 바꾸려면 config만 고침 |
| 시나리오 | 기본이 주, 확장(C5 제재 포함)은 추이 그림 점선 | 기본만 쓰면 됨(그림에 점선 들어 있음) |
| 완화 할인 | 실제 δ로 표시 | `완화할인_δ`(0~0.5)를 "완화 할인 n%"로 |

## 7. 10-30 갱신 (박성인 님 요청서 10-29/30 회신 — 구현 메인)
- 사건표 읽기 함수: `load_tension_events(scenario="기본")`를 `utils/loader.py` 끝에 추가합니다(F7b, 병합되면 알려 드립니다). 열은 CSV 이름 그대로 `사건ID · date(날짜형) · 요소 · 묶음 · S · 사건명` (기본 720건)이고 **`시작일` 열은 없습니다**(10-30 결정). 그래서 `pd.to_datetime` 줄만 지우면 `시작일`을 쓰는 곳이 깨집니다 — `시작일` 쓰는 곳을 `date`로 바꾸거나, 한 줄로 `events = load_tension_events().rename(columns={"date": "시작일"})` 하면 나머지 화면 코드는 그대로 둘 수 있습니다(고르는 건 담당자). 지금의 `# [임시]` 줄은 병합 전까지 그대로 두세요.
