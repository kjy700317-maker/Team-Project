## 2. 식 번호 밖이지만 일별 CSV에 있는 열

| `완화할인` | `1 − T / mean(Tg)` 을 다시 계산, 분모 0이면 0 | **δ와 같지 않은 날이 있다** `[주의]`: T⁺ = 0인 날은 δ > 0이어도 0으로 적힌다(v0.1.4 기본 35일, 첫날 2010-02-01 `[확인: 사건표_v014_기본으로 δ 재계산, 10-28]`. T⁺ > 0인 날은 δ와 |차| ≤ 0.0005 = 셋째 자리 반올림). 회귀 검산(열 값 일치)을 위해 이 정의를 그대로 이식하고, 바꿀지는 F2 보고서 "고치고 싶은 것"에 적는다 |

기준 구현의 일별 CSV는 `round(3)` 후 `utf-8-sig`(BOM)로 쓰고, 인덱스 이름 `날짜`. 열 수는 인덱스 제외 기본 20·확장 21, 6,144일(2010-01-01~2026-10-27) `[확인]`. 새 출력도 `utf-8-sig`로 쓴다(U13, 10-28).

## 3. 계산 끝날짜(END)
기준 구현은 `END = 2026-10-27` 고정. 새 코드는 `config.END_DATE`로 받는다 — 기본값 None = 실행일(U3, 10-28). **END는 과거 값을 바꾸지 않는다**(B_g·θ는 기준기간에서만, ⑫·⑬·⑭는 앞에서 뒤로만 계산) — 바뀌는 것은 `잠정` 열과 "현재" 요약 값뿐. 회귀 검산은 END = 2026-10-27로 호출한다.

## 4. 기준 구현의 알려진 문제 (규칙 변경 아님 — 이식할 때만 주의)
- `요약_v014.csv`의 `완화 상한에 붙은 날`이 **빈칸**이다: `run()`이 `R_완화`를 결과에 넣지 않아 조건문이 None을 낸다 `[확인]`. 정확값은 272(`v0.1.4\검산_log.txt` [3]). 새 코드는 272를 내야 하며, 이 칸만 기준 요약과 다르다 → F3 회귀 기준값은 272로 고정.
- 판정표 열 이름은 `판정근거(팀 요약 원문 문구)`(v1 지시서 5.2는 `판정근거`로 적었고 v2 부록 A.2에서 바로잡음) — F1 io 계약에서 실제 이름을 따른다.
- 인코딩: 사건표·일별 CSV는 UTF-8 BOM, 유형판정표(37행)는 BOM 없음 `[확인]` — 읽기는 `utf-8-sig`, 쓰기도 `utf-8-sig`(U13).
- 사건표는 헤더 포함 721줄 = **720행**(기본), 941행(확장).

## 5. F2 단계 나누기 (작업 프롬프트 안에서)
Claude Code 세션 2개(U5, 10-28): **F2-1 = 2a·2b**, **F2-2 = 2c·2d**. 단계마다 아래 검산을 통과해야 다음 단계로 간다.
- 2a ②③④⑤⑥⑦⑧ — 상승·완화 → `T_원값` 일치(최대차 < 0.001)
- 2b ⑩ — 하한 3종 → `하한_*` 열 일치
- 2c ⑨⑪⑫ — 구간·판정·하강 → `단계_T`·`단계_판정`·`단계_최종` 다른 날 0
- 2d ⑬~⑰ + 2절 열 — 표시·문구 → 일별 CSV 전 열 일치(실수 열 |차| < 0.001, 문자열·정수 완전 일치)
