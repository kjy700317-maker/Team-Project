## 2. 규칙 — ⑦에서 새로 확인한 것
- **GitHub 접근:** 이 환경에서 `add_repo`가 자동 모드 분류기에 두 번 거부됨(10-30) → 클라우드 clone·`gh api` 불가. **대신 PC `.git`을 tar로 묶어 가져와 클라우드에서 clone**: `cd 리포 && tar czf data/tension/_check/<새이름>.tgz .git`(깃 제외 경로 `data/tension/_*`) → `device_stage_files` → `tar xzf` → `chown -R` → `git clone <압축 푼 곳>/.git`. 원격 상태는 **PC가 마지막으로 fetch한 시점**까지만 보인다(PR 상태·mergeable·PR 본문은 `[미확인]` — 사용자에게 GitHub 화면 확인을 부탁). 지운 tgz는 사용자 정리 목록에 넣는다(연결 폴더는 rm 불가).
- **PC는 core.autocrlf=true.** blob이 CRLF인 파일(이제 `utils/real.py`)은 패치에 넣지 말고 바이트 편집 + `git -c core.autocrlf=false add`(F7c 방식). 시험본은 클라우드에서 `git -c core.autocrlf=true clone`으로 PC 흉내를 내 `git apply --check`·`hash-object`를 확인.
- **사용자가 pull할 때:** 기능 브랜치에 있는 채로 pull하면 그 브랜치가 앞으로 가고 로컬 develop은 그대로 남는다(10-30 실제로 생김) → 안내는 항상 `git switch develop` 먼저. 구현 메인은 **사용자가 develop으로 옮긴 뒤에** PC 문서를 고친다(앞서 고치면 switch가 막힘).
- **프로젝트 문서 쓰기:** `project_write(local_path)`는 메인 대화에서만, 그 파일을 **Read 한 번으로 끝까지** 읽은 뒤에만 된다(나눠 읽기·서브 에이전트는 거부). 큰 파일은 대화 초반에.
- Claude Code는 사용자 PC의 VS Code에서 돈다 — 그 세션 목록은 이 앱에 안 보여도 상관없다(작업은 리포의 작업 지시·보고서·커밋으로 이어짐).
