# 봉수 긴장도 운영 — 사건이 바뀌었을 때 결과를 다시 만드는 법

작성 2026-10-29 · 구현 메인 채팅 ⑥ · 대상 모델 `v0.1.4` · 코드 = F7 병합 시점 develop
위치: 리포 `docs/tension/운영.md`(정본, U8) · 프로젝트 `claude/운영.md`(사본)
표기: `[확인]` 코드·파일에서 직접 봄 · `[해석]` 확인한 것에서 추론 · `[미확인]` 직접 해 보지 않음
식과 값이 무엇인지는 `산출식.md`, 왜 바뀌었는지는 `산출식_변경이력.md`. 이 문서는 **"무엇을 언제 어떤 순서로 돌리나"**만 적는다.

명령은 모두 리포 루트에서, 팀 conda 환경 `python311`로 돌린다(`python` = 그 환경의 python). 앱(Streamlit)은 계산하지 않고 `data/tension/`의 결과 CSV만 읽는다(D1 — F0·F1 작업 프롬프트). 예외는 "가정 바꿔 보기" 한 곳 — 커밋된 사건표로 앱 안에서 다시 계산하고 "공식 결과가 아님"으로 표시한다(ADR-019, F8). 공식 결과를 바꾸려면 여전히 아래 절차로 결과 CSV를 다시 만든다.

## 2. 재계산 절차

### A. 사건·점수가 바뀌었을 때
```bash
# 0. 최신 develop에서 새 브랜치(feature/…)를 만든다 — develop에 직접 커밋하지 않는다
python scripts/build_events.py        # data/raw/긴장도_산출식_세부_기준/ → data/tension/events_기본.csv·events_확장.csv
python scripts/run_tension.py         # 사건표 → 일별·요약·월별·연도별·비교선·반감기 민감도 CSV (끝날 = 실행일)
python -m pytest                      # 아래 "기대 결과" 참고
git status                            # 바뀐 data/tension 파일만 있어야 한다
```
- 원자료 위치 `data/raw/긴장도_산출식_세부_기준/`(A~F 폴더)는 깃에 없다(로컬 전용, `.gitignore`의 `data/raw/*`) `[확인]`. 엑셀은 요소마다 파일 이름 패턴과 시트 이름으로 찾는다(`scripts/build_events.py` 위쪽 `EXCEL_ELEMENTS`) — 새 판 파일을 넣을 때 **같은 패턴·같은 시트 이름의 파일이 폴더에 정확히 하나**여야 한다(없거나 둘이면 멈춤).
- `build_events.py`는 같은 폴더에 `events_제외기록.csv`(뺀 행과 사유)와 `events_입력파일.csv`(읽은 파일의 크기·SHA256)도 쓴다. 둘은 **깃 제외**(`.gitignore`)이니 커밋하지 않는다. 제외기록은 한 번 훑어본다: 사유 코드(①③④⑤⑥⑦)와 뺀 행 수가 예상과 같은지.
- `run_tension.py`는 모든 시나리오가 끝까지 계산된 뒤에만 파일을 쓴다. 중간에 "멈춤: …"이 나오면 아무 결과도 바뀌지 않는다.
- 같은 명령에 날짜를 고정하려면 `--end YYYY-MM-DD`. **v0.1.4 회귀 검산용 끝날은 `2026-10-27`**(`tests/test_regression.py`가 자동으로 그 날짜로 돈다). 시나리오 하나만: `--scenario 기본`(확인용으로만 쓰고 `--out`을 다른 폴더로 준다 — 기본 폴더에 쓰면 요약·월별·연도별·비교선·민감도에서 확장 열·행이 빠지고 `일별_확장.csv`만 옛것으로 남아 어긋난다).
- **기대 결과(사건 점수가 그대로이고 끝날만 늘었을 때)**: 기존 날의 값은 바뀌지 않는다(B_g·구간은 기준기간에서만, 하강·표시선·누적 상위%는 앞에서 뒤로만 계산) `[확인: 식_함수_대응표 3절]`. 일별 CSV에서 바뀌는 것은 새로 늘어난 날의 행과 과거 행의 `잠정` 열뿐이다. 요약(`현재(…)` 행 이름과 값, 1~5거 비율·바뀜/년 같은 전체 평균), 반감기 민감도의 비율·현재, 월별·연도별의 마지막 기간, 비교선(늘어난 날만큼 행 추가)은 함께 바뀐다.
- **사건·점수를 바꾸면 v0.1.4 회귀 테스트(`tests/test_regression.py`)가 실패하는 것이 정상이다** — 기준이 v0.1.4 사건표이기 때문이다. 이때는 고치지 말고 **사용자(구현 메인과 함께) 결정**으로 넘긴다: 새 모델 버전 + `tests/fixtures/`에 새 기준 파일 추가(기존 파일은 수정 금지, `tests/fixtures/README.md`) + ADR 기록. 5절 참고.
- 확인할 숫자(결과가 의도대로인지): `요약.csv`의 `T구간(2·3·4·5거 시작)`, `경계_x.5_주의`(True면 사람이 확인), 위기 10건 단계, `현재(…)`·`현재 화면 단계`.

### B. 끝날만 늘릴 때
위 A에서 `build_events.py`를 빼고 `run_tension.py`부터 한다. 사건표 자체에 새 사건이 없으면 늘어난 날의 점수는 0에서 감쇠만 한다. 사건표에 들어 있는 마지막 사건 날짜를 `events_기본.csv`에서 확인하고, 그 뒤 날짜는 "자료 없음일 수 있음"으로 읽는다 `[해석]`(A2는 2024-11-05 이후 자료 자체가 없다 — `산출식.md` 9절).

### C. 결과를 올리는 법
`data/tension/`의 바뀐 CSV(일별 2 · 요약 · 월별 · 연도별 · 비교선_일별 · 반감기_민감도 · events_기본·확장)만 커밋한다. 커밋 전 `git diff --cached --name-only`에 `data/raw/`, `events_제외기록`, `events_입력파일`, `.json`, `_check/`가 없는지 본다. PR은 `develop` 대상(README 5절), 이슈 먼저. 커밋·PR·이슈에 AI 생성 표기를 넣지 않는다(팀 결정 10-29).

## 3. 새 물리 사건 판정 — 유형판정표 `data/tension/물리사건_유형판정표.csv`
- 대상: 사건표 `물리 충돌` 묶음의 **풍선이 아닌** A3·A7 사건(2010년 이후 37건, 이 중 4거 유형 Y 16건). 열 10개: `사건ID, date, 요소, S, 사건명, 판정유형, 4거유형, 봉수원뜻, 판정근거(팀 요약 원문 문구), 비고`. 열 이름·순서는 그대로(`io.load_type4_table`이 검사).
- **판정 원칙(단계 5 V1)**: 4거 유형 = Y는 **경계를 침범(넘음)·교전·사상자**가 있는 사건. 같은 포격이라도 NLL 남쪽 낙탄 언급이 없고 남측이 경고사격에 그치면 N(경계 접근 = 3거). 폭파는 경계를 넘지 않았으므로 N(3거). 작업 병력의 MDL 침범은 Y(4거). 근거는 **팀이 쓴 사건 요약 원문 문구**를 `판정근거`에 그대로 옮긴다. 원칙의 배경과 후보 비교: `단계5_값확정_결정자료.md` 1절.
- 절차: 새 사건을 읽고 `4거유형`을 Y/N으로 정해 한 행을 추가(날짜는 사건표의 `date`와 같게) → `run_tension.py`가 판정표와 사건표를 대조한다(날짜 불일치·사건표에 없는 ID·요소가 A3·A7이 아님이면 "멈춤") → 결과 CSV와 요약 `4거유형 사건 수`·`물리 4거유형 사건일 수`가 바뀐다.
- ⚠ **빠진 행은 코드가 알려 주지 않는다.** 대조는 판정표의 행이 사건표에 있는지만 본다 `[확인: io.check_type4_against_events]`. 새 비풍선 A3·A7 사건이 판정표에 없으면 조용히 N으로 처리된다. 새 사건을 받을 때마다 판정표 행을 **반드시 같이** 추가한다.
- 사망·침몰 5거는 판정표가 아니라 `config.KILL_EVENTS`(사건ID 목록)로 정한다. 새 사망·침몰 사건은 파라미터 변경이다 → 5절. 판정표에서 Y로 올려도 5거는 되지 않는다(4거 유형은 4거).
- 판정은 사람이 한다(자동 키워드 판정은 초안일 뿐). 판정을 바꾼 이유는 PR 본문에 남긴다.

## 4. GPR 월 갱신 (매월 초)
GPR 한국은 **비교 지수로만** 쓴다(ADR-002). 공식 월별 파일(https://www.matteoiacoviello.com/gpr.htm 의 Monthly GPR data, 매월 초 갱신)을 받아 `data/tension/GPR_한국_월별.csv`로 교체한다.
```python
import pandas as pd
d = pd.read_excel("Monthly GPR data_gpr_export.xls", sheet_name="Sheet1")   # .xls는 xlrd 필요(requirements에 없음)
d["month"] = pd.to_datetime(d["month"])
d = d[d["month"] >= "2010-01-01"][["month", "GPRC_KOR", "GPRHC_KOR"]].copy()
d["month"] = d["month"].dt.strftime("%Y-%m")
d.to_csv("data/tension/GPR_한국_월별.csv", index=False, encoding="utf-8-sig", lineterminator="\n")
```
- `[확인]` 이 코드를 프로젝트에 올라온 파일(마지막 월 2026-09)에 돌리면 지금 커밋된 `GPR_한국_월별.csv`와 **바이트까지 같다**(201행). 열은 `month, GPRC_KOR, GPRHC_KOR`, 월은 `YYYY-MM`. `.xls`를 읽으려면 xlrd가 필요하다 — `requirements.txt`에는 없다(openpyxl은 있음). 엑셀에서 `.xlsx`로 다시 저장해 `openpyxl`로 읽는 방법은 `[미확인]`.
- `io.load_gpr_monthly`가 읽을 때 검사한다: 열 이름·순서, 월 형식, 중복, 빈 값·숫자 아님이 있으면 멈춘다(빈 달을 0으로 두지 않음).
- GPR은 사건표·일별 결과에 영향이 없다. 바뀌는 것은 화면의 "봉수 vs GPR" 월별 비교와 그 요약(기간·달 수·상관)뿐이다. 요청서·문서에 적어 둔 "201달" 같은 숫자는 그 시점 값이다.
- 반감기 민감도(7·14·21·30일)와 비교선 T_basic은 `run_tension.py` 한 번에 같이 나온다 — 따로 돌릴 필요 없다 `[확인]`.

## 5. 파라미터를 바꿀 때 (식·값·묶음·단계)
단계 문턱 값(115/256/315/378)은 값이 아니라 **규칙**(기준기간 분위)이라 직접 바꾸지 않는다. 바꾸고 싶은 것이 있으면 순서대로:
1. **결정이 먼저**: 구현 메인과 사용자가 정해 `docs/decisions.md` ADR에 적는다(바꾸는 값·이유·언제). 이 문서의 담당자가 혼자 정하지 않는다.
2. `config.py` 8절의 해당 값을 고친다. `TENSION_MODEL_VERSION`을 올린다(예: v0.1.5).
3. 결과를 다시 만들고(2절 A) 회귀 테스트가 실패하는 것을 확인한다 — 기준이 바뀌었다는 뜻이다.
4. `tests/fixtures/`에 새 기준 파일(`v015_…`)을 **추가**한다. 기존 `v014_…`는 고치지 않는다. 기준을 바꾸는 것은 사용자 결정이다.
5. 화면 문구 상수가 새 숫자와 맞는지 본다: `utils/tension/screen.py`의 `DATA_COVERAGE`·`FOOTNOTES`·`READING_NOTES`(예: "±50% 흔들어도 86~91%")·`HALF_LIFE_NOTE`. 화면 파일 자체는 담당자(박성인)가 고친다.
6. 실험만 하고 싶으면 config를 고치지 말고 `core.daily_table(…, params={…})`로 넘긴다(쓸 수 있는 키 = `core.PARAM_KEYS`, 반감기 민감도·앱의 가정 바꿔 보기가 이 방식). 슬라이더 범위를 바꾸려면 `config.SLIDER_*`(ADR-019)를 고친다 — 공식 결과는 안 바뀐다. `config` 값은 import 때 함수 기본값으로 묶여서 실행 중에 바꿔도 반영되지 않는다(`BALLOON_KEYWORD`·`A2_NOTE`는 호출할 때 읽는다) `[확인: core.daily_table docstring · F7 패치]`.

## 6. 자료 이상 때 멈추는 경우 (0점으로 두지 않는다)
`run_tension.py`가 자료 이상으로 멈추면 터미널에 `멈춤: …`이 나오고 종료 코드 1이며 **결과 파일은 바뀌지 않는다**(파일은 모든 계산이 끝난 뒤에 쓴다 — 쓰는 도중 오류, 예: Windows에서 엑셀이 CSV를 열어 둔 경우는 예외 메시지로 끝나고 일부만 바뀔 수 있다). `build_events.py`는 `멈춤:` 접두어 없이 오류 메시지만 나오고 종료 코드 1이다. `--end`·`--scenario` 값이 틀리면 argparse가 usage를 찍고 종료 코드 2다. 원인을 고친 뒤 다시 돌린다.

| 어디서 | 멈추는 경우 |
|---|---|
| `build_events.py` | 요소별 엑셀·점수표 파일을 찾을 수 없거나 같은 패턴·시트의 파일이 둘 이상 · 사용여부 열이 없던 요소에 생기거나 있던 요소에서 사라짐 · 점수 열 값이 비었거나 숫자가 아님 · F2 분야 보정(φ) 대조 실패 |
| 사건표 읽기(`io.load_events`) | 열 이름·순서가 다름 · 같은 사건ID에 내용이 다른 행. (빈칸·날짜 형식·S가 숫자 아님·모르는 묶음·완전 중복 행은 **빼고 계속**한다. `run_tension`은 빼낸 행 수를 `load 제외 N`으로 출력할 뿐 파일로 남기지 않는다 — 0이 아니면 사건표를 직접 본다) |
| 판정표(`io.load_type4_table` · 대조) | 열 이름·순서 · `4거유형`이 Y/N 밖 · 사건ID 중복 · 날짜 형식 · (`run_tension`에서) 판정표에 4거 유형(Y) 사건이 없음 · 판정표↔사건표 날짜·ID·요소 불일치 |
| 계산(`core`) | 계산 기간이 기준기간(2010-01-01~2019-12-31)을 다 담지 않음(끝날 < 2019-12-31 또는 시작일 > 2010-01-01) · 평소값 B_g ≤ 0(기준기간 사건 0건, 완화 포함) · T 구간 첫 문턱 ≤ 0 · 사망·침몰 사건ID(`KILL_EVENTS`)나 4거 유형 사건ID가 사건표에 없음 · T 구간 분위·문턱이 4개가 아님 · `params`에 모르는 키 · 비교선 기준기간 평균 ≤ 0 |
| `run_tension.py` | `--end`가 `YYYY-MM-DD`가 아니거나 없는 날짜 · 사건표 파일 없음 |
| GPR(`io.load_gpr_monthly`) | 열 이름 · 월 형식 · 월 중복 · 빈 값·숫자 아님 |
- 요약의 `경계_x.5_주의`가 True면 멈추지는 않지만 사람이 본다: 분위가 정확히 x.5이면 짝수 반올림(`np.round`)이 의도와 다르게 갈 수 있다(`산출식.md` 9절).

## 7. 건드리기 전에 알아둘 것
- 열 이름·순서는 계약이다(화면이 읽는다). 결과 CSV·사건표·판정표의 열을 바꾸려면 구현 메인·화면 담당과 먼저 정한다.
- 묶음 이름은 `io.KNOWN_BUNDLES`에 고정이다 — 새 묶음은 io·config·`산출식.md`·화면을 함께 고쳐야 한다. 모르는 묶음이 사건표에 들어오면 `load_events`가 그 행을 빼므로 계산에서 조용히 빠진다(`load 제외 N`으로만 보인다).
- 단계는 5개(1~5거)다. T 구간은 문턱 4개를 가정하고 아니면 멈춘다. 단계 수를 바꾸는 일은 코드·화면 색·ADR을 함께 바꾸는 일이다.
- 감쇠 누적(③)과 하강(⑫), 누적 상위%(⑭)는 기준 구현과 같은 순서의 파이썬 루프다. 벡터화하면 같은 값이 나온다는 보장이 없다(동점 처리, 부동소수 순서) `[확인: core.py 주석]`.
- 화면 파일(`홈.py`·`pages/`)은 화면 담당 몫이다. 결과나 문구가 바뀌어 화면이 달라져야 하면 `docs/dev/requests/`에 요청서로 남긴다.
